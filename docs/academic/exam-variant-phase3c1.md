# Phase 3C.1 — private exam CLO evidence calculation (#1371)

Stacked on #1379 at 42b51ab (10/10 workflows passed). Keep draft.

## Existing policy and academic boundary
The existing QA engine in apps/backend/src/plugins/qa/evidence/clo-attainment.ts generates versioned official snapshots from published AND finalized results; it uses a configurable threshold with a software default of 50%. Existing marking-scheme evidence in core/academic/marking-scheme-evidence.ts uses earned/max per assessment and CLO. No approved RUPP threshold or approved policy version was identified in the inspected implementation. Do not treat 50% as institutional approval. This phase introduces no default threshold, no policy editing/approval mechanism and no official attainment snapshots. Explicit nullable what-if threshold is strictly diagnostic; later policy integration must resolve an approved effective policy and persist its identity/version and rule with official results. Existing official QA calculation and legacy single-paper paths are unchanged. Before enabling multi-variant exams, Phase 3C.2/3C.3 must integrate the released evidence with the existing QA engine, preventing incomplete course-level reporting.

## Acceptance and design
- Server-authorized exact programme, bound CourseSpec, assessment and offering; current enrollment, confirmed immutable assigned paper, exact grade revision, approved academic dossier, current sample outcome. Revalidate exact marking-scheme hash and every question/max/score using existing domain logic. A read-only serializable transaction loads roster, assignments, latest grades and current sample reviews; caches verified papers per hash. Scope limit 500 enrollments. No extra schema, migrations, permissions, canonical marks or QA snapshots.
- Separate direct and supporting evidence; one earned/maximum per learner/CLO/role, using original paper-specific question maxima. No parent marks or course assessment weight, no pooled raw cross-paper denominator, no inferred question marks. For section or variant summary, mean of available normalized learner percentages; threshold scenario rate is number meeting threshold divided by available direct-evidence students. Match existing per-assessment percentage rounding to two decimals. Supporting evidence never receives a threshold classification. This is exam-only; no claims of overall course CLO/PLO attainment.
- Explicit coverage: all enrollments, eligibility (active student and official ID), mapped/not mapped/unknown assignment, complete verified available evidence, missing mapped evidence. Unassigned, ungraded, incomplete, missing historical dossier, ineligible and current sample ChangesRequired are not treated as zero. A complete unsampled draft may be shown as provisional evidence (not release-ready); a genuine zero remains evidence. Sample acceptance is not a class-wide approval. Empty denominators and missing threshold return null. Partial exam contributes no earned points/percentage, even if some questions marked. Planned maxima may still be shown.
- Deterministic version and hash over scoped result, ordered enrollment rows and exact provenance, per-paper summaries, scenario and coverage. This is an integrity fingerprint of the preview, not a persisted official evidence artifact or proof of institutional approval. No confidential instructions, answer keys, comments or names in API report; frontend maps names from already authorized workspace roster.
- Existing isolated dev/test-only API and no-store authentication/authorization reused; staff UI exposes explicit calculation, per-paper and per-student inspection, and clear provisional/what-if labels. Preview is point-in-time; recalculate after changes. No public/student routes, release, exports or real grades.
