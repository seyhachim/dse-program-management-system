# Exam variant persistence — #1371 Phase 2A

Stacked on #1372. Parent #1355; pilot #1281. **Database foundation only; no activation.**

## Storage and invariants

The private `exam_variant` SQL schema follows the existing private-schema/raw-query pattern (e.g. lecturer_annual). Prisma declares only the four additive composite unique indexes on existing public parent models; the private tables are migration-owned and not exposed through Prisma model CRUD. No existing records are updated, deleted, or backfilled. No grade or assessment weight is duplicated.

- ExamConfiguration: one approved, active, individual, positively weighted assessment with no legacy instrument and no prior results. Exact course/programme/spec/assessment composite references. Immutable.
- ExamPaperVersion: exact variant ID/revision/hash and existing active marking scheme ID/hash; independently named preparer and approver, moderation reference. The ordered question definitions are stored as one JSONB array on the immutable row rather than separately insertable child rows. Trigger checks shape, distinct IDs, exact instrument question order/maxima, active assessment CLOs, evidence role, common exam maximum, and excludes extra properties such as answer keys. Revision and hash uniqueness, restrictive foreign keys, no update/delete/truncate.
- ExamOfferingPermission: exact version for a specific bound offering and matching course/spec/programme; immutable. A later phase can design audited retirement without deleting historical permission.
- ExamPaperAssignment: one row per enrollment/spec/assessment with exact offering membership and exact permission; only version changes with next revision and nonempty evidence/reason; no deletion. Existing result blocks insert/reassignment. Composite references protect against offering rebinding and enrollment movement. Lock offering before checking results (future service must lock offering before assignment row to align with result lifecycle).
- ExamAssignmentEvent: generated by trigger atomically on assignment insert or update, previous/new version, actor, reason, reference, revision and database timestamp. Append-only including truncate protection. Direct insert rejected. References previous/current permitted versions. This is not a proof of actor authorization; future server supplies identity and trusted records.

All tables RLS enabled with no Data API policies, explicit schema/table/function revocations and verifier inventory. Trigger functions are invoker functions with fixed search_path and fully qualified table names. Backend DB owner remains privileged as in existing PMS; not a defense against malicious DB administrators.

## Explicit limitations / release blockers

- No runtime service, authoring, approval, API, grade writes or feature flag is added. Keep all new tables empty in production until integrated acceptance. Approved CourseSpec creation/approval boundary and draft preparation must be implemented in 2B/2C; the current delete-and-rebuild draft authoring path must not create immutable bindings prematurely.
- SQL checks hash format and question consistency, **not recomputation of canonical hashes**. 2B must independently load the trusted rubric and approved CLO mapping, recompute rubricContentHash and Phase 1 snapshot hash, verify role/programme/assignment permissions, reviewer independence and source provenance; never accept client-supplied actor or approval claims. Do not infer paper assignments or scores. Source references must be opaque restricted references, not credentials, answers or student-identifying text.
- Existing grading and finalized correction paths are unchanged. Assignment guard refuses existing results but does not make legacy score writers variant-aware or guarantee a shared lock protocol with all current paths. Concurrency, grade/assignment interlock, variant-aware publication/correction and QA calculation must be completed in 2B/2C and Phase 3; no grading from these tables yet. Existing total-only historic marks need separate approved reconciliation, never fabricated question marks.
- Restrictive composite FKs intentionally prevent changing bound offering/spec/enrollment scope once evidence exists; no casual deletion/rebinding. Integrate friendly authorized lifecycle errors later. Existing approved spec editing/approval protections must be retained; SQL does not implement a full academic authorization workflow.
- This migration is new and additive; never edit previously applied migration files. Reserve timestamp 20261125180000 and recheck all active migrations before retargeting. Resolve overlap in schema, security verifier and CI with #1367, #1362, #1352, #1280/#1354, #1364, #1339, #1312 and other schema branches; #1365/#1277 before results integration. Merge #1372 only after independent review, then rebase/retarget and rerun combined CI. No production deployment authorized.

## Verification

The dedicated test is opt-in and refuses any connection except disposable local CI database dse_ci (CI=true, user ci, localhost, schema public). CI database job creates synthetic API roles/default privileges and applies migrations/seeds before running this test. Fixtures and audit rows are rolled back in a single interactive transaction. Tests cover scope, invalid definitions, immutability, atomic assignment audit, wrong section and stale revision, historic totals and effective API-role denial.

From repository root:
```sh
bun install --frozen-lockfile
bunx prisma validate --schema apps/backend/prisma/schema.prisma
bun run typecheck
bun run lint
bun run test
bun run test:backend
bun run build
```
Run the dedicated database job in GitHub Actions. For a separately provisioned disposable local dse_ci with the same CI role simulation and seed, run `CI=true EXAM_VARIANT_DB_TESTS=1 bun test apps/backend/src/core/academic/exam-variant-db.test.ts`, and `bun run --cwd apps/backend db:security:verify`. Never run against a production DB. Full exact-head CI, populated legacy-upgrade acceptance, concurrency and independent review are required before release. No actual TSA301 papers, answers, student identities or real grades are included.
