# Exam variant workspace — Phase 2C (#1371)

Stacked on #1374 at 9de617d; #1373 persistence and #1372 domain are prerequisites. No production activation or deployment.

## Workflow
Assigned lecturer selects an eligible exact offering/exam and own active marking scheme, explicitly maps each question to a CLO and direct/supporting evidence, verifies the server preview and submits its exact hash. Server re-derives snapshot before inserting durable Pending moderation. Distinct authorized coordinator/admin reviews the immutable metadata and approves with an opaque moderation reference or returns with a safe reason. Approval, version persistence, offering permission and terminal submission decision are atomic. Returned submissions remain immutable; new submissions are separate records. Coordinator explicitly permits versions for other offerings. Assigned lecturer confirms actual papers individually or in batches of up to 50 with reason, opaque evidence reference and expected revisions. All batch entries commit or roll back together. No grade writes; results block assignment. Staff can read scoped audit history. No question text, answers, file attachments or proposal signing tokens are exposed.

## Isolation
API is under /api/offerings/exam-variants/{workspace,preview,submit,decide,permit,assign,history,resolve}. All routes are authenticated, no-store, strictly validated and live-scope authorized. Disabled routes return 404. Pilot requires NODE_ENV development/test, EXAM_VARIANT_WORKSPACE_ENABLED=true, a loopback PostgreSQL URL naming dse_ci or dse_exam_uat, and EXAM_VARIANT_PROPOSAL_KEY set to a dedicated 64-hex-character random secret. Never use a tunnel to production or real data. Frontend link and page require NEXT_PUBLIC_EXAM_VARIANT_WORKSPACE_ENABLED=true; this public flag is not authorization. Never put the signing key in frontend config. No environment values have been changed. No production/staging DB accessed. Existing Phase 2B signed approval service remains internal; no legacy token approval API is exposed.

## Database and limits
Additive private ExamModerationSubmission table with exact offering/spec/course/programme FKs, pending revision uniqueness, immutable payload and terminal decision, independent decision actor and persisted approval proof, truncate/delete guards, RLS and revoked API grants. Security inventory updated. No existing migration rewritten. Workspace deliberately capped at 200 paper versions/submissions/instruments, 500 enrollments/history events; oversize fails closed. Batch max 50. Current scheme library is reused; do not create a second rubric system. Only metadata reference is recorded, not external evidence verification. Review retention, restricted evidence storage, actual moderation policy and role grants before release.
