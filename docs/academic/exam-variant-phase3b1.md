## Implementation

- Retain the marking-scheme library and immutable Phase 1 question rows; each independently scored sub-question is one leaf with its own original stable ID, maximum, CLO, and direct/supporting designation. Parent and component labels only group/display those leaves. A parent does not receive extra marks. To split an already approved aggregate question, prepare and moderate a new paper version before any grading; never reconstruct old results. No parallel marking scale or competency rubric.
- Exact permitted paper version gets one immutable open/approved academic dossier; returns remain historical and resubmission is separate. Author is an assigned lecturer, decision is a distinct scoped reviewer who did not prepare the paper. Immutable blueprint contains duration, conditions, topics, explicit Bloom levels, parent/component labels, restricted scheme and per-component answer references and partial-credit instructions. Server/DB derive and validate exact scored components, CLO/evidence, maxima, and reject duplicate labels and injected totals.
- First independently approved dossier becomes fixed baseline for the exact CourseSpec/assessment. Subsequent dossiers bind that baseline. Reviewer compares actual restricted documents, CLO and cognitive allocations, time/workload, difficulty, scoring and fairness, explicitly accepts all six checks and records rationale. Distribution is descriptive, not an automatic equivalence verdict. A stale pending baseline must be returned and resubmitted. An approved dossier cannot be overwritten. No inferred difficulty or forced identical CLO distributions.
- New grade revisions require approved exact dossier at service and DB boundary; existing drafts remain readable with NULL historical provenance. To reverify an old draft requires an explicit save of a new revision, never backfill or overwrite. Question feedback is optional, private, version-bound; omission retains prior comments and explicit empty list removes them in a new revision. No total/CLO calculation changes. A sampled complete grade revision can be accepted or returned for changes by a different reviewer; immutable sample review records reason and restricted evidence reference. Later grade revisions do not inherit prior sample acceptance. No grade publication, student-facing feedback or canonical result writes.
- Protected no-store endpoints and UI reuse isolated dev/test workspace. Two additive private RLS-protected tables; grade table receives additive nullable dossier FK and empty feedback default. Existing grade immutability and legacy grading fence remain in force.

## Scope limitations and release gates

Answer keys and marked scripts are NOT uploaded or stored here: opaque document references only, with private partial-credit instructions. Reviewers must independently verify controlled source documents; reference existence/access, actual exam quality and difficulty are not mechanically proven. Do not paste confidential solutions or identifiable student data into source or sample references. A source-document access/retention policy and secure evidence store integration remain gates. Sample moderation is manual per selected revision, not a statistically representative class sample plan. No class-wide readiness or release gate until Phase 3C, which must define sampling/feedback/appeals policy and prevent unresolved moderation from being published. Historical approved dossiers require a new paper version if the scoring plan changes. Outer navigation dirty-state protection and dedicated authenticated browser UAT remain outstanding.
